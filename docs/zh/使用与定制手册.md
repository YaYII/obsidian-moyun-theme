# 墨韵 MoYun · 使用与定制手册

本手册面向两类人：

- **使用者** —— 想知道怎么装、怎么调、哪些开关值得开（第一 ~ 三章）
- **定制者 / 贡献者** —— 想改样式、加模块、理解为什么这么写（第四 ~ 六章）

---

## 一、安装

### 1.1 手动安装

```bash
# 在你的库目录下执行
mkdir -p .obsidian/themes/"墨韵 MoYun"
cp theme.css manifest.json .obsidian/themes/"墨韵 MoYun"/
```

然后打开 Obsidian → 设置 → 外观 → 主题 → 选择「墨韵 MoYun」。

> 目录名与文件名都不要改：Obsidian 按 `manifest.json` 里的 `name` 匹配目录，
> 改名会导致主题列表里找不到它。

### 1.2 用 BRAT 自动更新

1. 安装社区插件 **BRAT**（Beta Reviewers Auto-update Tool）
2. 命令面板 → `BRAT: Add a beta theme`
3. 填入本仓库地址（如 `用户名/仓库名`）

BRAT 只从 GitHub Release 下载两个附件：`manifest.json` 与 `theme.css`。
主题**不需要** `versions.json` —— 那是插件的机制。

### 1.3 安装 Style Settings（强烈建议）

主题的全部可调项依赖社区插件 [Style Settings](https://github.com/mgmeyers/obsidian-style-settings)。

- **装之前**：主题依然完整可用，配色、排版、组件样式都是内置默认值，只是调不了。
- **装之后**：设置 → Style Settings → 找到「墨韵 MoYun」分组，六组共 30 多个可调项。

## 二、设置面板导览

### 🎨 配色

| 项 | 说明 |
|---|---|
| 主题色（八韵） | 八种中国传统色强调色，切换后链接、标签、按钮、选中态一起变 |

### 🀄 中文排版（本主题的核心）

| 项 | 默认 | 说明 |
|---|---|---|
| 首行缩进两字 | 关 | 打开后正文段落缩进 2 个汉字，列表/引用/代码/表格/公式/图片段落自动豁免 |
| 两端对齐 | 关 | 中文方块字适合两端对齐，但中西文混排时会产生字间空隙，按需开启 |
| 关闭中西文自动间距 | 关（即间距开启） | 默认在中文与英文、数字之间插入约 1/8 全角间隙 |

### 🔤 字体

| 项 | 说明 |
|---|---|
| 正文字体 | 留空则用主题内置的中文优先字体栈（逐级回退到系统已有字体） |
| 标题字体 | 同正文；改动可获得书籍感 |
| 标题改用衬线字体 | 开关。打开后标题用宋体，正文保持黑体 |
| 代码字体 | 建议包含中文等宽回退（更纱等宽黑体 / Maple Mono） |
| 正文字号 | 12 ~ 24px，中文推荐 16px 起步 |

### 📐 行距与版心

| 项 | 默认 | 说明 |
|---|---|---|
| 正文行高 | 1.8 | 中文汉字密度高，1.8 是舒适区；1.5 以下明显拥挤 |
| 段落间距 | 0.85em | 开启首行缩进时建议调小 |
| 正文行宽 | 46rem | 约 34 个汉字，中文一行 30~40 字最易阅读 |
| 中文字距 | 0 | **推荐保持 0**：字距会在每行最后一个字之后也追加空隙，破坏右边缘对齐 |

### 🖥 界面细节

紧凑文件树 / 隐藏功能区 / 标签页标题居中 / 隐藏笔记内大标题 / 圆角大小

### ✨ 内容增强

彩虹文件夹 / 标题自动编号 / 标题下划装饰 / 图片编号与题注 / 卡片化列表 / 沉浸模式 / 扁平标注样式

## 三、能力边界（先读这一节，能省下很多折腾）

有几件中文排版上很想要的事，在当前 Obsidian 的渲染引擎里**做不到**。这里如实列出：

| 想要的效果 | 现状 | 原因 |
|---|---|---|
| 标点挤压 | 声明了但**无效果** | 依赖字体的 `chws` 特性，而思源黑体 / Noto Sans CJK 只有 `halt` / `palt`。可用「紧凑标点」开关替代（基于 `halt`，会把全角标点压半角） |
| 标点悬挂 | **不支持** | Chromium 从未实现 `hanging-punctuation`（只有 Safari 有） |
| 避头尾 | 无需干预 | Chromium 默认**已强制**执行中文避头尾；主题保留 `line-break: strict` 仅为防御性声明 |
| 按词组智能断行 | 仅日文有效 | `word-break: auto-phrase` 依赖引擎内置词典，Chromium 只随附日文词典 |
| 实时预览下标题编号 | **不支持** | CodeMirror 虚拟滚动，屏幕外的行没有 DOM，CSS 计数器会随滚动跳变。宁可只在阅读视图编号 |
| 竖排 | 阅读视图可用 | 编辑模式的 CodeMirror 对 `writing-mode` 支持不完整，光标定位会错乱（见 `snippets/竖排诗文.css`） |

## 四、定制

### 4.1 先理解三层令牌

```
第一层  原始色板      src/00-tokens/palette.css      --my-ink-*  --my-qinghua-*
        组件层禁止直接使用。换色只改这一层。

第二层  语义令牌      src/00-tokens/tokens.css       --my-surface-*  --my-text-*  --my-accent
        组件层应当使用这些。改它们能一致地影响全局。

第三层  Obsidian 映射 src/00-tokens/obsidian-map.css  --background-*  --text-*（778 个）
        组件层可以优先使用这些，因为它们跟随用户的外观设置。
```

### 4.2 用 CSS 片段做轻量定制

把下面的内容存成 `.obsidian/snippets/我的调整.css`，在设置 → 外观 → CSS 代码片段里启用：

```css
/* 收窄版心、放宽行高 */
body {
  --my-content-width: 40rem;
  --my-line-height-relaxed: 2.0;
}

/* 整体换成自定义强调色（会连带 hover / 选中态 / 标签 / 按钮） */
body { --my-accent-custom: #7a5c3e; }

/* 只改阅读视图里的引用块底色 */
.markdown-rendered blockquote {
  background-color: color-mix(in oklab, var(--my-accent) 8%, transparent);
}
```

完整令牌白名单见 `docs/dev/token-contract.md`。

### 4.3 单篇笔记的排版（cssclasses）

```yaml
---
cssclasses:
  - my-govdoc
  - my-heading-numbers
---
```

可用的类见 `demo-vault/速查手册.md`，或用 Obsidian 打开 `demo-vault/` 直接看效果。

## 五、开发

### 5.1 常用命令

```bash
npm install                    # 仅测试需要依赖，构建与校验零依赖

node build.mjs                 # 构建 theme.css 并做 8 类静态校验
node build.mjs --watch         # 监听 src/ 变化自动重建
node build.mjs --check         # 只校验不写文件（CI 用）
node tools/check-conflicts.mjs # 模块冲突检查（--strict 供 CI 使用）
npm test                       # 契约回归测试（24 项）
node tools/verify.mjs          # 视觉与计算样式验证（需本机 Chrome）
node tools/make-demo-vault.mjs # 重新生成演示库
```

### 5.2 构建期会拦住什么

| 检查 | 级别 | 为什么 |
|---|---|---|
| 花括号不配对 | 错误 | 一个多余的 `}` 会让后面所有规则错位 |
| 引用未定义的 `--my-*` 令牌 | 错误 | 拼写错误是最常见的静默失效来源 |
| `hsl(var(--my-*-rgb) / α)` | 错误 | RGB 三元组不能用于 `hsl()`，整条声明会被浏览器**静默丢弃** |
| 自定义属性自我引用 | 错误 | `--x: var(--y, var(--x))` 会让 `--x` 在计算值阶段失效 |
| 缺少 `@settings` 块 | 错误 | Style Settings 将无法识别主题设置 |
| 组件层引用原始色板 | 警告 | 破坏分层，换色时不会跟着变 |
| 组件层写死颜色 | 警告 | 同上，且暗色模式下往往不可读 |
| 含动效但缺 `prefers-reduced-motion` 兜底 | 警告 | 无障碍要求 |
| `text-transform` 对中文无效 | 警告 | 汉字没有大小写 |
| `!important` 超过 3 处 | 警告 | 通常意味着在硬对抗原生样式，值得复核 |

### 5.3 加一个新模块

1. 在对应层目录下新建 `.css`（命名用英文小写连字符）
2. 文件开头写**中文说明块**：用途、依赖、关键取舍
3. 只消费语义令牌或已映射的 Obsidian 原生变量，不写死颜色
4. 同时适配阅读视图（`.markdown-rendered`）与实时预览（`.markdown-source-view.mod-cm6`）
5. 含动效就补 `prefers-reduced-motion` 兜底
6. `node build.mjs` → `node tools/check-conflicts.mjs` → `npm test`

### 5.4 视觉验证台

`tools/preview/harness.html` 用**Obsidian 真实的 DOM 结构 + 真实的 app.css + 主题产物**渲染一篇中文样张，
因此不必打开 Obsidian 就能验收。`node tools/verify.mjs` 会：

- 断言 28 项**计算后样式**（行高、中西文间距、豁免规则、对比度、组件圆角……）
- 计算关键文字的 WCAG 对比度，低于 4.5:1 即判失败
- 输出日间与夜间各 3 张分段截图到 `tools/preview/out/`

> 维护提示：`tools/preview/harness.html` 里显式补了两处 Obsidian 由 JS 在运行时设置的布局
> （侧栏宽度 270px），否则静态 HTML 下侧栏会撑满视口、把编辑器挤出可见区。

### 5.5 发布

```bash
# 同步 manifest.json 与 package.json 的版本号，然后
git tag v1.0.0 && git push origin v1.0.0
```

GitHub Actions 会自动构建、校验、检查版本号一致性，并创建带 `manifest.json` 与 `theme.css` 两个附件的 Release（BRAT 直接可用）。

### 5.6 发布后必须做的两项校验（血泪教训）

**① 校验资产要用「下载实际文件」，不要用下载链接的缓存，也不要只信 digest。**

这个坑有两个面，都踩过：

| 方法 | 问题 |
|---|---|
| `curl .../releases/latest/download/theme.css` | 该路径有 **CDN 缓存**，刚发布会拿到**旧版本文件**，误判为「CI 产物与本地不一致」 |
| `gh api .../releases/latest --jq '.assets[].digest'` | 该字段在 release **刚创建时有延迟**，可能返回上一个 release 的 digest，同样误判 |

可靠做法是用 `gh release download`（走带签名的直链，不经 CDN 缓存），再逐字节比对：

```bash
gh release download <tag> --repo <用户名>/<仓库> --dir /tmp/rel --clobber

sha256sum theme.css            /tmp/rel/theme.css
sha256sum manifest.json        /tmp/rel/manifest.json
cmp theme.css /tmp/rel/theme.css && echo 一致
```

> 如果确实不一致，`diff theme.css /tmp/rel/theme.css` 能直接指出差异行 ——
> 构建不可复现时（例如产物里写了生成时间）就会在这里暴露。

**② 确认构建产物可复现。**
`theme.css` 的头部曾写入生成时间，导致相同源码每次构建产出不同文件，
CI 的产物因此永远无法与本地对上。现已移除时间戳；模块排序也从 `localeCompare`
（依赖运行环境的 ICU 版本，跨 Node 版本可能乱序）改为码位序直接比较。
改动构建逻辑后，用这条命令自检：

```bash
node build.mjs && sha256sum theme.css
node build.mjs && sha256sum theme.css   # 两次结果必须完全相同
```

## 六、设计决策记录

这些是本主题在开发中做过的关键取舍，记下来避免后来者重复踩坑：

| 决策 | 选择 | 理由（含实测证据） |
|---|---|---|
| 首行缩进单位 | `2em` | 实测：16px 下 `2em` = 32px = 2.000 个汉字；`2ch` = 17.77px = 1.110 个汉字（`ch` 是数字 0 的宽度）。社区大量教程用 `2ch`，差 45% |
| `text-autospace` 写法 | 显式声明 `normal`，默认生效 | 实测三家浏览器都把初始值实现成 `no-autospace`（偏离规范），不写就没有；也不能写成「加了类才开」，否则未打开设置面板的用户静默失效 |
| 标点挤压 | 保留声明 + 提供 `halt` 替代开关 | 实测 `text-spacing-trim` 对 Noto Sans CJK 零效果（字体无 `chws` 特性） |
| 避头尾 | 仅防御性声明 | 实测六种 `line-break` 取值断行结果完全一致 —— Chromium 默认已强制 |
| 智能断行 | 只对 `lang="ja"` 开启 | 实测 `auto-phrase` 对中文无效果（引擎只带日文词典） |
| 标题字重 | 650 | 汉字在 700 以上时笔画粘连，14~18px 尤其明显 |
| 中文斜体 | 关掉伪斜体，改变色 + 半粗 | 汉字无真斜体，强行倾斜字形失真；另提供着重号方案 |
| 夜间正文色 | 宣纸色 `#d9d4ca`，非纯白 | 纯白在深底上对比过强，是夜间阅读疲劳的主要来源 |
| 中文字距默认 | 0 | 字距在每行最后一字之后也追加空隙，破坏右边缘对齐 |
| 实时预览不编号 | 有意不支持 | 虚拟滚动会让 CSS 计数器跳变，给错不如不给 |
