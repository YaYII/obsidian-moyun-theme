# 开源 Obsidian 主题调研报告 · 面向「中文优先」自研主题

> 调研对象：Minimal / AnuPpuccin / Blue Topaz / Border / Maple / Primary / Things / Catppuccin / Sanctum（+ Everforest、Gruvbox 作为配色对照）
> 方法：`git clone --depth 1` 全部仓库，直接通读 SCSS/CSS/TS 源码与 Style Settings 块，统计行数与选择器。
> 结论口径：所有特性、选择器、变量名均来自源码实证，非二手描述。

---

## 零、一句话结论

**九成英文主题的中文支持是零。** 实测统计：CJK 字体族名在 9 个主题中的命中分布为 —— Blue Topaz 21 处、**其余 8 个主题合计 0 处**。
Maple 是唯一在「中文优先」上做到工程级的主题（双语 Style Settings + 行高 1.8 + 段落缩进 + CJK 等宽字体内嵌）；
Blue Topaz 是唯一在「中文字体栈」上做到底的主题。**其余七个可借鉴布局、配色与工程化，但排版层不可借鉴。**

## 一、逐主题提取

### 1. Minimal — kepano/obsidian-minimal

| 项 | 事实 |
|---|---|
| 主 CSS | `theme.css` 8,707 行 / 265 KB（另出 `Minimal.css` 兼容旧名） |
| 源文件 | **91 个 SCSS**，`src/scss/index.scss` 为 @use 清单 |
| 构建 | 自研 `build.js`（dart-sass JS API + chokidar --watch） |

**最被喜爱的 2–3 个特性（具体到选择器）**

1. **图片自动网格（Image Grid）** —— 用 `:has()` 实现「一行多图自动等分」：

~~~scss
body { --image-grid-fit: cover; --img-grid-gap: 0.5rem; }
@media (max-width:400pt) { body { --img-grid-gap: 0.25rem; } }
.img-grid-ratio { --image-grid-fit: contain; }

.img-grid .markdown-preview-section {
  :is(div, p):has(> :is(.image-embed, img) ~ :is(.image-embed, img)) {
    display: grid;
    margin-block: var(--img-grid-gap);
    grid-column-gap: var(--img-grid-gap);
    grid-row-gap: 0;
    grid-template-columns: repeat(auto-fit, minmax(0, 1fr));
    > img { object-fit: var(--image-grid-fit); align-self: stretch; }
    > .internal-embed img { object-fit: var(--image-grid-fit); align-self: center; }
  }
  > div:has(img) > p { display: grid; grid-template-columns: repeat(auto-fit, minmax(0,1fr)); > br { display:none; } }
}
~~~

关键点：`p:empty`、`img ~ br`、`.image-embed ~ br` 全部 `display:none`，把 Markdown 硬换行产生的空段落吃掉。

2. **块级宽度助记类（.table-wide / .img-100 / .map-max）** —— 通过「容器变量间接层」让助记类在**任意层级**（全局 body / 单篇 cssclasses / 元素级）都生效，无需写长选择器：

~~~scss
body {
  --container-table-max-width: var(--max-width);
  --table-max-width: none;
  --table-width: auto;
  --table-margin: inherit;
  --table-wrapper-width: fit-content;
  --container-img-width: var(--line-width);
  --container-img-max-width: var(--max-width);
  --img-max-width: 100%;
}
/* 助记类只改变量，不写选择器 */
.table-wide  { --container-table-width: var(--line-width-wide); --container-table-margin: auto; }
.table-max   { --container-table-width: var(--max-width); }
.table-100   { --container-table-width: 100%; --table-max-width: 100%; --table-width: 100%; }
.img-wide    { --container-img-width: var(--line-width-wide);
               --img-margin-start: calc(50% - var(--line-width-wide)/2); }
.img-100     { --container-img-width: 100%; --img-margin-start: 0; }
.wide { --line-width: var(--line-width-wide); }
.max  { --line-width: var(--max-width); }
~~~

消费侧统一：

~~~scss
.cm-table-widget,
> div:has(table) {
  width: var(--container-table-width);
  max-width: var(--container-table-max-width);
  margin-inline: var(--container-table-margin) !important;
}
~~~

> 源码注释原话：「The benefit of this approach is that it covers all levels of specificity wherever the helper is applied: global, per file, and element-level.」

3. **6 标量驱动整套配色** —— 见 B 节。

**文件组织**：SCSS 最大化模块化，`index.scss` 按 9 组带注释分区：
`Variables / Obsidian app / Components / Content / Minimal features / mobile / Core plugins / Community plugins / Color schemes`。
**Style Settings 不在 SCSS 里**，单独放 `src/css/style-settings.css`（纯 CSS），构建时把它**拼在最后**。

**构建脚本关键逻辑**（可直接复刻）：

~~~js
const themeCss = [license, expanded, pluginCompat, styleSettings].join('\n');
fs.writeFileSync('theme.css', themeCss);
// 本地开发：把 theme.css 拷进测试库
if (process.env.OBSIDIAN_PATH && process.env.HOME) { /* ... */ }
~~~

配合 `.env` 里的 `OBSIDIAN_PATH`，改完自动进 vault。

**Style Settings 组织**：id `minimal-style`；顶层全部 `type: heading level: 2 collapsed: true`；
配色项用 `type: variable-themed-color`，其中 `id: base` 用 `format: hsl-split`，`bg*`/`ui*` 用 `format: hex` + `opacity: true`。

**配色/排版独到之处**：HSL 标量派生的 15 个语义令牌（`--bg1-3` / `--ui1-3` / `--tx1-4` / `--ax1-3` / `--hl1-2` / `--sp1`），
于是 15 套配色方案（gruvbox / catppuccin / nord / everforest / rose-pine / solarized / dracula / atom / ayu / sky / macos / things / flexoki / eink）**每套只要约 30 行**。

**中文/CJK 支持：无。**
`--font-editor-theme:-apple-system,BlinkMacSystemFont,"Segoe UI",Roboto,Inter,Ubuntu,sans-serif` —— 无一款中文字体，全部靠逐字回退。
`--font-ui-smaller: 11px`（汉字 11px 已不可读）。
标题变体提供 `small-caps / all-small-caps`（6 个选项）——**对汉字完全无效**，中文用户选了看不到任何变化。

### 2. AnuPpuccin — AnubisNekhet/AnuPpuccin

| 项 | 事实 |
|---|---|

**最被喜爱的特性**

1. **彩虹文件树（Rainbow File Browser）** —— `:nth-child(11n+N)` 循环发色 + `inherit` 实现子文件夹继承父色：

~~~scss
.nav-folder-children > .nav-folder,
.nav-files-container > div > .nav-folder,
[data-type="bookmarks"] .tree-item {
  &:nth-child(11n + 2) { --rainbow-folder-color: var(--ctp-red); }
  &:nth-child(11n + 3) { --rainbow-folder-color: var(--ctp-maroon); }
  /* … 至 11n+12 … */
}
/* 只让第一层循环，深层继承父色 */
.anp-rainbow-subfolder-color-toggle {
  .nav-files-container .nav-folder.nav-folder .nav-folder { --rainbow-folder-color: inherit; }
}
~~~

配合 `--anp-full-rainbow-text-inverted`、`--anp-rainbow-folder-bg-opacity` 做前景反色。

2. **44 套扩展配色作为「片段（snippets）」而非塞进主题** —— 分离：

~~~
snippets/src/ext-colorschemes/*.scss   →  snippets/extended-colorschemes.css
snippets/src/notion-cards.scss         →  snippets/notion-cards.css
~~~

`make snippets` 单独构建。用户想要哪套就开哪个片段，主题本体不膨胀。

3. **14 强调色 × 4 用途的 SCSS 循环生成**：

~~~scss
$accents: "rosewater","flamingo","pink","mauve","red","maroon","peach","yellow",
          "green","teal","sky","sapphire","blue","lavender";
@each $accent in $accents {
  .anuppuccin-accent-toggle.ctp-accent-#{$accent} { --ctp-accent: var(--ctp-#{$accent}); }
  .anp-bold-#{$accent}      { --anp-bold-color: var(--ctp-#{$accent}); }
  .anp-italic-#{$accent}    { --anp-italic-color: var(--ctp-#{$accent}); }
  .anp-highlight-#{$accent} { --anp-highlight-color: var(--ctp-#{$accent}); }
}
~~~

**配色板即数据**（SCSS map）：

~~~scss
$theme-frappe: (
    ctp-rosewater: #F2D5CF, ctp-flamingo: #EEBEBE, ctp-pink: #F4B8E4,
    ctp-mauve: #CA9EE6, /* … 26 项 … */
~~~

**Style Settings**：单一 `@settings` 块在 `src/modules/Core/style-settings.scss`，id `anuppuccin-theme-settings`，
用 `# Colors` / `# Editor` 这种注释行做视觉分隔，再套 `type: heading level: 1`。

**最被喜爱的特性**

1. **Style Settings 用 TypeScript DSL 生成（独家）**

~~~ts
export default Settings.create('maple-basic', 'Maple Basic').children([
  Settings.ofLevel(1, { title: { en: 'Colors', zh: '颜色' }, open: true })
    .addClassToggle('color-dark-dim-disable', {
      title: { en: 'Disable Opacity Reduction in Dark Mode',
               zh: '深色模式下，颜色的不透明度不降低' },
    })
    .addVarNumSlider('setting-line-height',
      { title: { en: 'Line Height', zh: '行高' },
        desc:  { en: 'Multiple of text size', zh: '文字大小的倍数' } },
      { default: 1.8, min: 1.2, max: 2.4, step: 0.1 }),
])
~~~

`generator.ts` 里的关键设计：

~~~ts
type Translate = { en: string; zh: string }
function flattenDoc(doc: Doc) {
  return { title: doc.title.en, 'title.zh': doc.title.zh,
           description: doc.desc?.en, 'description.zh': doc.desc?.zh }
}
const CN_NUMBERS = ['一','二','三','四','五','六']   // 标题层级用中文数字
// 自动 kebab-case + 由标题自动生成 id
function kebabCase(str){ return str.replace(/([a-z])([A-Z])/g,'$1-$2')
  .replace(/[^a-zA-Z0-9.]+/g,'-').replace(/^-+|-+$/g,'').toLowerCase() }
// 版本号注入设置头
const settings = '/* Maple Theme v' + version + ' For Obsidian */'
~~~

方法集：`addInfo / addClassToggle / addClassSelect / addVarText / addVarNum / addVarNumSlider /
addVarSelect / addVarColor / addVarThemedColor / addColorGradient`。
**5 个模块分工**：`basic / workspace / editor / plugin / mobile`。

2. **中文排版的两个默认值就是正确答案**

~~~ts
.addVarNumSlider('setting-line-height',
  { title: { en: 'Line Height', zh: '行高' } }, { default: 1.8, /* ← 不是 1.5 */ })
.addVarNumSlider('setting-editor-p-indent',
  { title: { en: 'Paragraph Indent', zh: '段落缩进' },
    desc: { zh: '当文档属性的 cssclasses 中存在 "p-indent" 类时，为所有段落添加缩进' } },
  { default: 2, min: 0, max: 4, step: 0.2 })
~~~

~~~scss

  p > br {
    content: ''; white-space: pre;
    &::after { content: '\000A\200B'; margin-inline-end: var(--indent); }
  }
}
~~~

3. **内嵌 CJK 等宽字体 `maplemono`（`local()` 链，零下载）**

~~~scss
@font-face {
  font-family: 'maplemono';
  font-display: swap;
  src: local('Maple Mono NF CN Regular'),
       local('Maple Mono CN Regular'),
       local('Maple Mono NF Regular'),
       local('Maple Mono Regular'),
       font('regular') format('woff2');
}
.font-maple-text      { --font-text-theme: 'maplemono'; }
.font-maple-interface { --font-interface-theme: 'maplemono'; }
.font-maple           { --font-monospace-theme: 'maplemono'; }
~~~

**利器：让 Style Settings 覆盖主题而不用 `!important`**

~~~scss
@mixin use-no-plugin($selector, $suffix: '') {
  body:is(:not(.css-settings-manager), #{string.unquote($selector)})#{string.unquote($suffix)} { @content; }
}
@mixin var-color($name, $color) {          // 生成「可调透明度」的三元组令牌
  $rgb: color.channel($color,'red',$space:rgb), color.channel($color,'green',$space:rgb),
        color.channel($color,'blue',$space:rgb);
  --color-#{$name}-rgb: #{$rgb};
  --color-#{$name}: rgba(var(--color-#{$name}-rgb), var(--color-opacity));
}
@mixin use-icon($icon-name, $color: none, $size: none) {
  -webkit-mask: icon($icon-name) no-repeat;   // iconify 构建期内联
  -webkit-mask-size: 100% 100%;
}
~~~

**配色独到**：HSL 三元组 + `max()` 做透明度下限：

~~~scss
--bg-editor: hsla(var(--background-primary-hsl),
                  max(var(--bg-opacity), var(--editor-min-opacity)));
~~~

~~~scss
}
~~~

### B. 配色体系设计法

#### B1 · 四层命名分层（实测最稳，也是 MoYun 已采用的结构）

| 层 | 文件 | 命名 | 约束 |
|---|---|---|---|
| L0 原始色板 | `palette.css` | `--my-ink-0…975`、`--my-<色系>-<档>` | 只允许字面量；禁止 Obsidian 变量；禁止选择器 |
| L1 语义令牌 | `tokens.css` | `--my-surface-primary`、`--my-text-muted`、`--my-accent` | 只允许 `var(--my-*)`；换肤/换模式在此层翻转 |
| L2 Obsidian 适配 | `obsidian-map.css` | `--background-primary: var(--my-surface-primary)` | 只允许 `var(--my-*)` 与字面量；禁止组件选择器 |
| L3 组件 | `src/2x-*` | 只消费 Obsidian 原生变量 | 禁止直接引用 `--my-*`（尺寸/圆角除外） |

收益：**换肤只动 L1，换 Obsidian 版本只动 L2**，组件层零改动。

#### B2 · 「标量驱动」法（Minimal / Things / Maple 共通）

只需 6 个标量即可生成整套配色：

~~~css
body {
  --base-h: 0;     --base-s: 0%;    --base-l: 96%;     /* 底 */
  --accent-h: 201; --accent-s: 17%; --accent-l: 50%;   /* 强调 */
}
.theme-light {
  --bg1: hsl(var(--base-h), var(--base-s), var(--base-l));
  --ui1: hsl(var(--base-h), var(--base-s), calc(var(--base-l) - 6%));
  --ui2: hsl(var(--base-h), var(--base-s), calc(var(--base-l) - 12%));
  --tx1: hsl(var(--base-h), var(--base-s), calc(var(--base-l) - 90%));
  --tx2: hsl(var(--base-h), calc(var(--base-s) - 20%), calc(var(--base-l) - 50%));
  --ax1: hsl(var(--accent-h), var(--accent-s), var(--accent-l));
  --ax2: hsl(var(--accent-h), var(--accent-s), calc(var(--accent-l) - 8%));
  --hl1: hsla(var(--accent-h), 50%, calc(var(--base-l) - 20%), 30%);
}
.theme-dark {
  --base-l: 15%; --accent-l: 60%;   /* 只翻两个标量，其余自动跟随 */
}
~~~

**一套配色主题 = 覆盖 6 个标量 + 8 个 `--color-*-rgb`，约 30 行。**（Minimal 15 套方案实证）

#### B3 · 通道三元组（可调透明度的关键，必用）

CSS 无法对 `#RRGGBB` 变量加 alpha，必须存「裸通道」：

~~~css
:root { --my-accent-rgb: 42 111 138; }          /* 裸通道，无 rgb() 包裹 */
.a { color: rgb(var(--my-accent-rgb)); }
.b { background: rgb(var(--my-accent-rgb) / 0.12); }
.c { box-shadow: 0 0 0 3px rgb(var(--my-accent-rgb) / 0.25); }
/* HSL 版（Maple 用法）：两者都存，按需取 */
.theme-light { --background-primary-hsl: 38, 40%, 98%; }
.card { background: hsla(var(--background-primary-hsl), var(--my-opacity, 1)); }
~~~

SCSS 生成器（照抄 Maple）：

~~~scss
@mixin tone($name, $color) {
  --my-#{$name}-rgb: #{color.channel($color,'red',$space:rgb)}
                     #{color.channel($color,'green',$space:rgb)}
                     #{color.channel($color,'blue',$space:rgb)};
  --my-#{$name}: rgb(var(--my-#{$name}-rgb));
}
@include tone('accent', #2a6f8a);
~~~

#### B4 · 全局透明度旋钮

~~~css
:root { --my-opacity: 1; }
.my-soft-ui { --my-opacity: 0.82; }   /* 一处切换，全局生效 */
~~~

#### B5 · 强调色分发（八韵 / 十四色）—— SCSS `@each`

~~~scss
$tones: (qinghua: #2a6f8a, zhusha: #b23a34, zhuqing: #4a7c59, tengzi: #7a5fa0,
         qiuxiang: #a8892f, daiqing: #2f5d5a, yanzhi: #a8496b, songyan: #5a5651);
@each $name, $hex in $tones {
  .my-tone-#{$name} {
    @include tone('accent', $hex);
    --my-accent-soft: rgb(var(--my-accent-rgb) / 0.12);
    --my-accent-line: rgb(var(--my-accent-rgb) / 0.35);
  }
}
~~~

#### B6 · 严格四层色彩角色（照 Catppuccin 的 26 角色）

~~~
强调层  accent
文本层  text / text-muted / text-faint / text-on-accent
覆盖层  overlay-0/1/2 → surface-0/1/2 / border / border-strong
表面层  bg-0/1/2 / panel / hover / active
~~~

**规则：组件不得自造新色，只能从这 4 层里取。** 这条规则直接决定换肤能否成功。

#### B7 · 主题类命名约定（多配色共存）

~~~css
.theme-dark.my-scheme-moye, .theme-light.my-scheme-xuanzhi { /* … */ }
~~~

Minimal 用 `.theme-dark.minimal-gruvbox-dark`，Maple 用 `.theme-light.color-use-minimal` ——
**「模式 + 方案」双类名**，避免暗色方案污染亮色。

### C. Style Settings 组织最佳实践

**C1 · 双语键是真实存在的官方能力（最重要的一条）**

`title.zh` / `description.zh` 被 Style Settings 插件识别并按界面语言切换。
实证：Blue Topaz（几乎每条）、Border（几乎每条）、Maple（TS DSL 强约束）。

~~~yaml
- id: my-indent-on
  title: First-line indent          # 英文界面显示
  title.zh: 首行缩进两字              # 中文界面显示
  description: Indent the first line of every paragraph by 2 characters
  description.zh: 每个段落首行缩进两个汉字宽度
  type: class-toggle
~~~

**只写中文 `title` 会让英文用户看到中文**；正确做法是「英文作基底 + `.zh` 覆盖」。

**C2 · 块结构与分组**

~~~yaml
/* @settings
name: 墨韵 MoYun
id: moyun
settings:
  -
    id: group-typography
    title: "🀄 中文排版"
    description: 本主题核心。以下选项专为中文阅读优化
    type: heading
    level: 1
    collapsed: false          # 核心分组默认展开
~~~

- `level` 只用 1/2/3，不要更深；
- 顶层分组一律 `collapsed: true`，**只展开最想让用户改的那一组**；
- 每组的 `id` 用 `group-<域>` 前缀，便于 preset JSON 引用。

**C3 · 一个 CSS 文件可含多个 `@settings` 块**（Border 用 7 个）

~~~
Info / Components / Appearance-light / Appearance-dark / Editor / Mobile / Plugin
~~~

好处：明暗配色分离、preset JSON 三段键对得上、团队分工不冲突。

**C4 · 全部可用控件类型（实测清单）**

| type | 用途 | 关键参数 |
|---|---|---|
| `heading` | 分组 | `level`, `collapsed` |
| `info-text` | 面板内文档 | `markdown: true` |
| `class-toggle` | 布尔开关 | `default` |
| `class-select` | 单选类 | `allowEmpty`, `options[{label,value}]` |
| `variable-text` | 任意 CSS 值 | `quotes` |
| `variable-number` | 数值 | `format: px` |
| `variable-number-slider` | 滑杆 | `min`, `max`, `step`, `format: ms/vh` |
| `variable-select` | 变量单选 | `options` |
| `variable-color` | 颜色 | `format: hex/rgb/hsl/rgb-split/hsl-split/hsl-split-decimal` |
| `variable-themed-color` | 明暗双色 | `default-light`, `default-dark`, `opacity: true` |
| `color-gradient` | 渐变 | `from`, `to`, `step`, `pad` |

**C5 · 版本号注入设置头**（Maple）—— 用户报 bug 时能直接看到主题版本：

~~~ts
const settings = '/* Maple Theme v' + version + ' For Obsidian */'
~~~

**C6 · 由标题自动生成 id + 自动 kebab-case**（Maple）—— 消除手写 id 的不一致：

~~~ts
const id = config.id ?? ['title', ...config.title.en.split(' ').map(s => s.toLowerCase())].join('-')
~~~

**C7 · 中文数字编号标题层级**（Maple）—— 中文用户读「三级标题」比「Level 3 Heading」快：

~~~ts
const CN_NUMBERS = ['一','二','三','四','五','六']
title: { en: 'Level ' + level + ' Heading', zh: CN_NUMBERS[level-1] + '级标题' }
~~~

**C8 · 文档不要塞进设置面板**（Primary）—— 用 `info-text` 只放链接，正文放独立文档站。
反面教材：Blue Topaz 30,450 行 CSS 中夹着大量设置描述。

**C9 · 发布可导入预设 JSON**（Border，34 套）—— 键格式：

~~~json
{ "<@settings 的 id>@@<条目 id>@@<dark|light>": "<值>" }
~~~

官方文档站给的导入/导出就是这个协议，用户可复制粘贴后重启生效。
**对中文主题的价值**：可把「宣纸 / 墨夜 / 竹简 / 秋香」等整套外观打包成预设分发。

**C10 · 把可选功能做成片段（snippets）而非内置**（AnuPpuccin）

44 套扩展配色、notion-cards、floating-search-bar 全部独立构建成 `.css` 片段放 `snippets/`，
用户按需开启。主题本体因此保持在约 9,000 行。

**C11 · 让主题能被覆盖**：`body:is(:not(.css-settings-manager), X)`（Maple）或 `:not(.css-settings-manager)`（Catppuccin）。

**副作用提醒**：`body` 上的 `--my-*` 定义若写在 `.css-settings-manager` 排除链里，会连用户片段一起屏蔽，需谨慎选择作用点。

**D1 · 标准发布 Action（Obsidian 官方模板，Primary 直接抄了文档）**

~~~yaml
name: Release Obsidian Theme

  push:

jobs:
  build:

    permissions: { contents: write }
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with: { node-version: lts/* }
      - run: npm ci && npm run build
      - run: |
          tag="${GITHUB_REF#refs/tags/}"

        env: { GITHUB_TOKEN: "${{ secrets.GITHUB_TOKEN }}" }
~~~

**注意 `--draft`**：Minimal / Primary 都先发 draft，人工确认后再 publish。

**D2 · 供应链证明（Minimal 独有，值得抄）**

~~~yaml
    subject-path: |
~~~

**D4 · 双产物兼容旧名**：同时输出 `theme.css` 与 `obsidian.css`（后者是 Obsidian 1.0 前的旧名，仍有老用户）。

**D6 · `manifest.json` 最小字段**

~~~json

  "author": "…", "authorUrl": "…", "fundingUrl": "" }
~~~

**D7 · BRAT 支持**：**主题无需任何额外文件**。BRAT 直接读 GitHub Releases 的

并且 tag 用语义化版本（BRAT 会比较版本号决定是否更新）。

**D8 · 质量门禁（Catppuccin 独有，强烈建议加）**

~~~json
"devDependencies": {
  "stylelint": "^16",

  "stylelint-config-idiomatic-order": "^10",
  "stylelint-declaration-block-no-ignored-properties": "^3"

~~~

`stylelint-declaration-block-no-ignored-properties` 能自动抓出

正是中文主题最容易堆垃圾的地方。

**D9 · 源码模块编号 + 构建期排序**（Primary 的 `10_/20_/30_/40_/50_/60_`）
比 `@use` 清单更直观，且新增文件不需要改入口。

**D10 · 构建期静态校验**

把它接进 CI 即可作为 PR 门禁。

### E. 中文排版的缺口（英文主题对中文用户不友好的具体点）

> 实测方法：对 9 个主题的 CSS/SCSS 全文 grep 关键属性。

| 属性 | 命中主题数 | 说明 |
|---|---|---|
| CJK 字体族名（PingFang / 微软雅黑 / 思源 / 霞鹜…） | **1 / 9**（仅 Blue Topaz，21 处） | 其余主题零中文字体 |
| `line-break`（中文禁则 / 避头尾） | **0 / 9** | 完全没有 |
| `text-autospace`（中西文自动间距） | **0 / 9** | 完全没有 |
| `text-spacing-trim` / `text-spacing`（标点挤压） | **0 / 9** | 完全没有 |
| `hanging-punctuation` | **0 / 9** | 完全没有 |
| `text-justify: inter-ideograph` | **0 / 9** | Border 只写了 `text-justify: auto` |
| `text-indent`（首行缩进） | **1 / 9**（仅 Maple，且需手动加 `cssclasses: p-indent`） | Minimal / AnuPpuccin 的命中全是 `text-indent: 0`（重置） |
| `font-feature-settings` 用于 CJK | **0 / 9** | 只有 `'tnum'`（Minimal）、`'calt'`（Maple）等西文特性 |

**E1 · 没有中文字体回退 → 逐字回退，中西文「两张脸」**

~~~css
/* 主题实际写法（Minimal） */
--font-editor-theme: -apple-system, BlinkMacSystemFont, "Segoe UI", Roboto, Inter, Ubuntu, sans-serif;
~~~

用户把正文字体设成 Inter / 霞鹜文楷时，**汉字没有归处**，浏览器逐字回退到系统默认字体，
结果：英文用 Inter、汉字用宋体，**字面高度不一致 → 行内基线跳动、行距忽宽忽窄**。

正确写法（Blue Topaz 的做法）：

~~~css
--font-text-theme: "LXGW WenKai Screen", "PingFang SC", "Microsoft YaHei",
                   "Noto Sans SC", "Source Han Sans SC", sans-serif;
--font-monospace-theme: "Maple Mono NF CN", "Sarasa Mono SC", "等距更纱黑体 SC",
                        "Microsoft YaHei Mono", Consolas, monospace;
~~~

> 关键：**中文字体必须显式出现在栈里**，不能依赖逐字回退。等宽字体若不含汉字，
> 代码块里的中文注释会退化成比例字体，**列对齐直接崩掉**（Blue Topaz 用「等距更纱黑体 SC」解决）。

**E2 · 行高按西文设 → 汉字拥挤**

Minimal `--line-height: 1.5`、Sanctum `--line-height-normal: 1.5`。
汉字是满格方块、笔画密度远高于拉丁字母，1.5 在长文下明显压抑。
**唯一做对的是 Maple：`default: 1.8`。** 中文正文行高实测区间 1.7–1.9。

**E3 · 段界不清**

Minimal `--p-spacing: 1.75rem`（相对西文偏小）；多数主题只有 `margin-block` 没有首行缩进，
中文读者**无法一眼看出段落从哪开始** —— 这是中文阅读最本质的需求，九个主题里八个没有。

**E4 · 界面小字号对汉字不可读**

Minimal `--font-ui-smaller: 11px` / `--font-ui-small: 13px`。
拉丁字母 11px 尚可，**汉字 11px 已糊**（汉字有效笔画空间约为同字号拉丁字母的 1/4）。
中文界面最小字号建议不低于 12px，正文不低于 15px。

**E5 · `small-caps` 对汉字是死设定**

Minimal 在 Style Settings 里为 h1–h6 各提供 `small-caps / all-small-caps`（6 个选项），
`--h5-variant: small-caps; --h6-variant: small-caps` 还是**默认值**。
汉字没有大小写，`font-variant: small-caps` 对汉字**零效果** ——
中文用户点了半天，界面毫无变化。**中文主题必须移除这类选项。**

**E6 · `text-transform: uppercase` + `letter-spacing` 滥用**

Minimal 给文件树 / 反向链接标题加 `letter-spacing: 0.05em`（`plugins-core/file-explorer.scss`）。
拉丁小标题加宽字距好看，**汉字加宽则松散**（汉字本就等宽满格，不需要额外字距；
反而需要 `letter-spacing: -0.01em` 轻微收紧）。`text-transform: uppercase` 对汉字也是空操作。

**E7 · 两端对齐没有中文专用参数**

Blue Topaz 的 `text-align: justify; hyphens: auto;`：
`hyphens` 对汉字**完全无效**（汉字无连字符分词），真正需要的是
`text-justify: inter-ideograph`（汉字间伸缩）而非 `auto`（词间伸缩）。
用错参数的后果：中文段落被拉出「河流（rivers）」，字距不均。

~~~css
.justify { text-align: justify; text-justify: inter-ideograph; text-align-last: start; }
~~~

**E8 · 断行按字符硬切，词被劈开**

中文没有空格，浏览器默认 `word-break: normal` 会在任意汉字间断行（可接受），
但**中英混排时**会把英文单词劈成两半。全部主题都用 `word-break: break-word` 兜底，
这是**过度宽松**的写法。正确组合：

~~~css
line-break: strict;          /* 标点不出现在行首（中文禁则） */
word-break: normal;          /* 汉字间可断，英文词内不断 */
overflow-wrap: anywhere;     /* 超长 URL 才强制断 */
word-break: auto-phrase;     /* Chromium 新版：按语义短语断行 */
~~~

**E9 · 标点占满全角 → 版面「漏气」**

中文 `，。！？：；` 在字体里占 1em 宽，行首 / 行尾 / 相邻连续标点会留下大片空白。
九个主题**全部没有**处理。现代 Chromium 已原生支持：

~~~css
text-spacing-trim: space-first;               /* 连续标点挤压 */
font-variant-east-asian: proportional-width;  /* 标点按比例宽而非全角 */
~~~

**E10 · 中西文之间没有间隙**

中英混排时「在Obsidian里写Markdown」几个字会糊在一起。九个主题全部没有处理。

~~~css
text-autospace: normal;    /* Chromium 120+，自动在 CJK 与拉丁/数字间插 1/4 空格 */
~~~

**E11 · 汉字合成粗体（`font-synthesis`）糊笔画**

汉字字体往往只有 Regular 一档，浏览器用算法加粗 → **笔画粘连、字面变糊**，
在标题（字号大、笔画多）上最明显。
Blue Topaz 是唯一记录此问题的主题（README 要求加粗改用「霞鹜文楷屏幕版」）。

~~~css
:root { font-synthesis-weight: none; }   /* 禁止合成粗体，改用真实字重 */
h1, h2, h3, strong, b {
  font-family: "LXGW WenKai Screen R", "Source Han Sans SC Heavy", var(--my-font-text);
  font-weight: 700;
}
~~~

> 注意：`font-synthesis-weight: none` 在字体确实没有 bold 时会让加粗**失效**，
> 必须配一个「有真粗体的中文字体栈」才有意义。

**E12 · 设置界面对中文用户是英文的**

Minimal / AnuPpuccin / Primary / Things / Sanctum / Catppuccin **全是纯英文**，
一个中文用户面对 300+ 条英文设置项。
只有三家做了本地化：Blue Topaz（全量 `title.zh`）、Border（全量 + `README.zh.md`）、Maple（TS 强约束双语）。

**E13 · PDF 导出与打印**

`@media print` 下中文断行规则常常丢失（Border `theme.css:6925` 有 `text-align: justify` 但无 `line-break`），
导出后出现行首标点。中文主题需在 print 媒体查询里重复声明 `line-break: strict`。

**E14 · 网页剪藏 / 中英混排表格**

表格里中文与数字混排时，汉字等宽、数字比例宽，**列宽抖动**。
Minimal 用 `font-feature-settings: 'tnum'`（等宽数字）解决了一半，
中文侧还需 `font-variant-east-asian: proportional-width` 才对称。

## 三、对「墨韵 MoYun」的落地建议

调研中核对了本仓库现状（`src/00-tokens/{palette,tokens,obsidian-map,settings}.css`、
`src/10-foundation/typography.css`、`build.mjs`），结论如下。

### 已经领先于全部九个主题的地方（保持）

1. **四层令牌分层**（palette → tokens → obsidian-map → 组件）—— 九主题中无一做到这个严格度（Minimal 只做两层）。
2. **中文排版用上了原生 CSS Text 4**：`text-autospace: normal`、`text-spacing-trim: space-first`、
   `line-break: strict`、`word-break: auto-phrase`、`text-wrap: pretty/balance`、
   `text-justify: inter-ideograph`、`font-variant-east-asian: proportional-width`、
   `text-indent: var(--my-indent-cjk)`。
   **E 节表格里 0/9 命中的属性，MoYun 已全部覆盖** —— 这是本主题最硬的差异化，值得在 README 里写成卖点。
3. **行高 / 字距独立成组**（中文行高单列一组），比 Maple 的单一 slider 更系统。
4. **`build.mjs --check` 静态校验**（括号配对、未知令牌、Style Settings 块、禁用词）——
   九个主题里没有一个有这层门禁。

### 建议补的缺口（按性价比排序）

| # | 缺口 | 依据 | 建议做法 |
|---|---|---|---|
| 1 | **无 CI / 无 Release 自动化** | D1–D2 | 加 `.github/workflows/release.yml`：tag `v*` → `npm ci && npm run build` → `gh release create "$tag" --draft manifest.json theme.css`；再加 `attest-build-provenance@v2`。BRAT 只认 release 里的这两个 asset。 |
| 2 | **Style Settings 缺英文基底** | C1 | 现为纯中文 `title`（0 处 `.zh:`）。若要走出中文圈，改为「英文 `title` + `title.zh` 覆盖」；若定位纯中文用户，可在 README 明确声明，也是可接受的取舍。 |
| 3 | **无预设分发机制** | C9 | 把「宣纸 / 墨夜 / 竹简 / 秋香」等整套外观导出成 preset JSON，键格式 `"moyun@@<条目id>@@<dark或light>"`，放 `presets/` 并写 `presets.md`。 |
| 4 | **可选功能未拆片段** | C10 | `snippets/` 目前为空。彩虹文件夹、卡片列表、题注等做成独立 snippet，主题本体保持精简。 |
| 5 | **缩进只支持全局开关** | A13 / A14 | 现为全局 `my-indent-on`。补 Maple 式 `cssclasses: my-indent` 支持**单篇**缩进，并确认缩进白名单（代码块/列表/表格/callout）无漏。 |
| 6 | **无可自检的 CSS 质量门禁** | D8 | 引入 stylelint + `stylelint-config-idiomatic-order` + `stylelint-declaration-block-no-ignored-properties`，专门抓「对中文无效的声明」（`small-caps`、`hyphens` 等）。 |
| 7 | **未内嵌 CJK 等宽字体** | E1 | 用 Maple 的 `@font-face + local()` 链（零下载、无版权风险）给代码块兜底中文字体，避免中文注释列对齐崩坏。 |
| 8 | **`font-synthesis-weight` 未处理** | E11 | 标题 / 加粗处禁止合成粗体，并配真实粗体中文字体栈（参考 Blue Topaz 的霞鹜文楷屏幕版经验）。 |
| 9 | **print 媒体查询未重复中文断行规则** | E13 | 在 `@media print` 内重新声明 `line-break: strict` 与 `text-justify: inter-ideograph`，保证 PDF 导出质量。 |
| 10 | **界面最小字号** | E4 | 核对 `--font-ui-smaller` 一类令牌不低于 12px。 |

### 一句话定位

九个主题里，**布局可抄 Minimal，配色体系可抄 Minimal + Catppuccin，
Style Settings 工程化必须抄 Maple，发布流程抄 Minimal / Primary，预设分发抄 Border**。
**而「中文排版」这一层，MoYun 已经在他们前面 —— E 节 0/9 的每一项都是可防守的技术护城河。**
